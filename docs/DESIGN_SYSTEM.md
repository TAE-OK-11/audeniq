# AUDENIQ 디자인 시스템

스튜디오(아티스트 화면)·관리자·업무 화면이 함께 쓰는 **토큰**과 **공통 컴포넌트**입니다.
같은 역할의 요소는 화면이 달라도 이 한 벌만 씁니다. 미리보기: 관리자 `/admin/design`.

| 위치 | 내용 |
|---|---|
| `web/studio/app/src/styles/tokens.css` | 색·글자·모서리·높이·간격·그림자·움직임 토큰 (단 하나의 기준) |
| `web/studio/app/src/styles/ui.css` | 공통 컴포넌트 클래스 `ui-*` |
| `web/studio/app/src/ui/` | React 컴포넌트 (`import { Button, Badge, … } from '../ui'`) |
| `web/studio/app/src/admin/pages/DesignSystem.tsx` | 살아 있는 견본 화면 |

## 규칙
1. 화면 CSS는 **배치(폭·여백·정렬·그리드)** 만 바꿉니다. 색·크기·모서리는 컴포넌트와 토큰이 정합니다.
2. 숫자 대신 토큰: `var(--aq-text-3)`, `var(--aq-r-xl)`, `var(--aq-h-sm)` …
3. 누르는 요소 높이는 8px 단위 4단계(32·40·48·56). 모서리는 높이에 비례.
4. 윤곽선·그림자 없이 면 색으로 구분합니다. 호버는 면 색만 바뀝니다.
   입력칸은 토스처럼 선 없는 면이되 색은 AUDENIQ 회색(`--aq-field` = `--aq-gray-100` #EEF1F6)이고, 포커스는 윤곽선·그림자 없이 면이 옅은 파랑(`--aq-field-focus-bg` = `--aq-blue-150`)이 되고 칸의 이름표도 파랗게 바뀝니다(회색 한 단계로는 쓰는 중인 칸이 구분되지 않았다). 옅은 카드 안에서는 흰 칸 → 포커스 때 `--aq-blue-100`. 아직 고르지 않은 필수 선택칸은 안내 글자 색입니다. 고를 것이 8개를 넘는 선택칸은 휴대폰에서 아래 시트로 열리고, 시트의 손잡이·제목은 위에 붙어 있습니다. 탭이 몇 개 안 되는 곳(`Tabs className="is-fill"`)은 휴대폰에서 폭을 똑같이 나눕니다. 고른 줄·선택한 은행처럼 '켜짐' 표시도 테두리 대신 진한 면으로 합니다. 버튼·고르기 칸 안에 동그란 표시(라디오 점, 동그란 배경의 아이콘·체크)를 넣지 않습니다. 고른 칸은 면 색과 글자 색으로, 여러 개 고르는 칸은 배경 없는 체크로만 보여요. 키보드로 이동할 때 버튼·링크·체크박스에만 포커스 표시가 남습니다(접근성).
5. 색 규칙: 보완 필요 = 주황, 거절·오류 = 빨강, 검토 중 = 보라, 완료 = 초록. 상태를 보여 주는 알약은 모두 상태 배지(`Badge`, `.ui-badge`) 하나의 모양(둥근 알약 · 12px 굵은 글자 · 옅은 바탕 + 진한 글자)만 씁니다. 화면마다 따로 알약을 만들지 말고, DSP 이름·번호·파일처럼 '정보'를 붙이는 이름표만 네모난 `Tag`를 씁니다. 발매 상태(작성 중·보완 필요·검토 중·발매 완료 등)는 처음 쓰던 상태 칩 모양 그대로 `Badge`에 `aq-status is-<상태>`를 붙여 씁니다(11px · 옅은 바탕 + 상태 색 글자).
6. 버튼은 놓인 면에 맞춰 스스로 바뀝니다 (`.ui-card` 위에서는 한 단계 진하게, `.ui-dark` 위에서는 반전). 상태 색 면(주황 보완 · 빨강 오류 · 초록 완료) 위에서는 버튼·기본 아이콘 칸도 그 색을 따릅니다 — 새 상태 면은 `.ui-tone-warn` / `.ui-tone-danger` / `.ui-tone-success`를 붙이면 됩니다.
7. 글꼴은 **Audeniq Sans** 하나입니다(굵기 45–930 자유). Pretendard 1.3.9를 바탕으로 어데닉 화면에 맞게 다듬은 서체로, 원본과 빌드·검사는 `tae-ok-11/audeniq-font` 저장소에 있어요. 파일은 각 앱 `public/static/fonts/`(자주 쓰는 한글 2,780자 판 + 그 밖의 한글이 나올 때만 받는 전체 판, OFL 라이선스 동봉), `@font-face`는 `tokens.css` 맨 위, `index.html`은 자주 쓰는 판을 미리 받아요. 같은 출처(`font-src 'self'`)라 CSP에 외부 주소가 필요 없어요. 화면 CSS에 `font-family`를 직접 쓰지 말고 `var(--font-body)`를 씁니다.
   - 한글 자간 −0.02em이 글꼴 안에 들어 있어요. 화면 CSS의 `letter-spacing`은 Pretendard 때보다 0.02em 넓게 씁니다(본문 −0.02em → 0, 제목 −0.04em → −0.02em). 새 화면도 이 기준으로 써 주세요.
   - 금액 앞 `-`는 글꼴이 빼기 기호 `−`로, 띄어 쓴 ` · `, ` — `, 한글 뒤 `…`, 한글을 감싼 ‘ ’는 글꼴이 문맥에 맞는 모양으로 바꿔요. 문구에서 따로 바꿀 필요가 없어요.
   - 굵기는 Pretendard보다 조금 가볍게 보여요(400 → Pretendard 390, 700 → 650 무게).
8. 아이콘은 직접 그린 SVG만 씁니다(`components/Glyph.tsx`, 설문은 `survey/app/src/Icon.tsx`). 이모지와 아이콘처럼 쓰는 글자 기호(₩ ✓ › ‹ ▸ ↗ ⚠ 등)는 기기마다 모양이 달라서 쓰지 않아요. CSS로 그릴 때는 `--aq-icon-check`·`--aq-icon-chevron`을 mask로 씁니다. 문서 아이콘도 이모지 대신 아이콘 이름을 저장하고, 예전 이모지는 비슷한 SVG로 바꿔 보여 줍니다. 문장 속 화살표(→)처럼 글자로 읽히는 것은 Audeniq Sans에 들어 있어 그대로 둡니다.
9. 글자 단계: 크기는 11 · 12 · 13 · 14 · 15 · 16 · 18 · 22px와 큰 제목(`--aq-fs-h1` 28–36, `--aq-fs-display` 30–40)만 씁니다(`--aq-fs-2xs`~`--aq-fs-title-lg`). 굵기는 400(본문) · 600(보조) · 700(제목·버튼) · 800(숫자·큰 제목) 네 가지뿐입니다. 글자 회색은 `--aq-text` · `--aq-text-2` · `--aq-text-3` · `--aq-text-4` · `--aq-text-disabled` 다섯 단계만 쓰고, 회색 hex나 `--aq-gray-*`를 글자색으로 직접 쓰지 않아요. 카드 제목(h2)은 18px/700, 페이지 제목(h1)은 `--aq-fs-h1`입니다.
10. 라벨은 한글로 씁니다. 페이지 위 작은 분류 글자(eyebrow), 관리자 메뉴 묶음 이름, 단계 이름 모두 한글이고 영어 대문자 라벨(MONTHLY REPORT 등)은 쓰지 않아요. 고유명사(Spotify, UPC/EAN, ISRC)만 예외입니다.
11. 선택 상자와 날짜는 기기 기본 팝업(iOS 휠·안드로이드 목록·기본 달력)을 쓰지 않습니다. 앱 루트의 `<SelectHost/>`가 모든 `<select>`를 AUDENIQ 선택 시트로 열고(휴대폰은 아래에서 올라오는 시트, 넓은 화면은 칸 아래 작은 창), 날짜·시간은 `components/Picker.tsx`의 `<DateField>`(날짜) · `<DateTimeField>`(날짜+시간) · `<TimeField>`(시간) · `<MonthField>`(달)을 씁니다. `<input type="date|datetime-local|time|month">`는 새로 쓰지 않아요. 기본 팝업이 꼭 필요한 곳만 조상에 `data-native-select`를 붙입니다.
12. 여러 입력칸을 한 묶음으로 보일 때는 `fieldset.ui-group`을 씁니다. 브라우저 기본 fieldset 테두리·legend 선은 쓰지 않아요(전역 초기화). 선택 칸은 라벨에 `(선택)`을 붙이지 않고 `<span className="aq-optional">선택</span>`, '비우면 …' 같은 규칙은 라벨 괄호가 아니라 칸 아래 도움말(`<small>`)로 씁니다.
13. 새 역할이 생기면 화면 CSS에 만들지 말고 `ui.css` + `src/ui`에 더하고 견본 화면에 올립니다.
14. 상태 표시: 오류 칸(`aria-invalid`)은 입력 중에도 붉은 면을 유지합니다. 막힌(비활성) 입력칸은 회색 면 + 흐리게, 비활성 버튼은 주 실행(파란) 버튼과 '저장 중'을 빼면 회색 면·회색 글자입니다.
15. 체크박스·라디오 모양 값은 `controls.css`의 `--aqc-*` 변수 하나로만 정합니다(`enhance.css`는 그 값을 적용만). 옅은 면(카드·목록 줄·체크 줄) 위에서는 회색 칸에 옅은 테두리를 더합니다.
16. 휴대폰(760px 이하)에서는 입력칸 글자를 16px 이상으로 둡니다(아이폰 사파리 확대 방지). 터치 기기에서 작은 탭·글자 버튼은 보이는 크기는 그대로, 누르는 영역만 44px로 넓힙니다. 검색칸(`type=search`)은 검색어가 있을 때 지우기 버튼이 나옵니다.
17. 되돌릴 수 없는 일을 묻는 확인 창(`useConfirm({ danger: true })`)의 실행 버튼은 진한 빨강(`is-danger-solid`)이고, 처음 포커스는 '닫기'에 둡니다. 옆으로 넘치는 칩·탭 줄은 더 밀 수 있는 쪽 끝을 흐리게 합니다(`lib/rowNav.ts` → `aq-more-left/right`). 선택 칸·입력칸에 다 안 들어가는 글자는 '…'로 끝납니다. 날짜·시간·달 칸(`DateField` 등)은 놓인 곳과 상관없이 입력칸(`ui-input`) 모양입니다.
18. 움직임은 들어올 때와 나갈 때가 짝입니다. 선택창·달력은 닫힐 때 내려가며(작은 창은 줄어들며) 사라지고, 펼친 폼은 닫힐 때 접힙니다(`lib/expand.ts`). 탭 내용은 누른 탭이 있는 쪽에서 들어옵니다(`lib/rowNav.ts`). 폼 검사에서 걸린 칸은 `revealField()`(`lib/motion.ts`)로 부드럽게 옮겨 커서를 두고 한 번 흔듭니다 — `focus()`를 먼저 부르면 화면이 순간이동하니 쓰지 않아요. 동작 줄이기 설정이면 움직이지 않습니다.
19. 움직임 기준(`tokens.css`): 시간은 `--aq-motion-short`(0.16초, 누름·색·작은 창 닫힘) · `--aq-motion-base`(0.24초, 선택창·메뉴·토스트) · `--aq-motion-long`(0.32초, 창·시트·탭 내용·목록 줄) · `--aq-motion-page`(0.4초, 페이지 전환 전체) 네 단계, 곡선은 `--aq-enter`(들어올 때, 아이폰과 같은 `cubic-bezier(.32,.72,0,1)` — 첫 프레임에 툭 튀지 않고 길게 감속) · `--aq-exit`(나갈 때) · `--aq-pop`(배지·체크 같은 작은 확인 표시 — 지금은 `--aq-enter`와 같음) 세 가지만 씁니다. 목표를 넘었다 돌아오는 튀는 움직임은 어디에도 쓰지 않습니다. 휴대폰 아래 창·선택 시트는 `--aq-sheet-ease`로 `--aq-motion-sheet`(0.46초) 동안 올라오고 `--aq-motion-sheet-out`(0.34초) 동안 끝까지 내려가며, 정해 둔 시간이 아니라 닫힘 애니메이션이 끝난 프레임(animationend)에 화면에서 뺍니다. 목록·덩어리는 줄마다 차례로 나타내지 않고 한 번에 나타나며, 떠오르는 거리는 4~6px입니다. 호버로 아이콘·표지를 기울이지 않습니다. 휴대폰 아래 창은 바닥에서 끝까지 올라오고 끝까지 내려갑니다. 새 화면 CSS에 초·곡선 숫자를 직접 쓰지 말고 이 토큰을 씁니다. UX 기준: ① 화면 안 요소의 등장은 0.32초(`--aq-motion-long`)를 넘기지 않습니다 — 길어질수록 느리게 느껴집니다. ② 자주 보는 움직임일수록 짧고 작게: 화면 이동·목록은 `--aq-motion-base`. ③ 작은 창·메뉴는 누른 칸 쪽에서 자라납니다(`transform-origin`을 칸 가운데로, 칸 위에 열리면 아래에서). ④ 나갈 때는 들어올 때보다 짧게. ⑤ 완료 축하 연출이 있어도 다음 할 일(버튼)은 1초 안에 누를 수 있게 합니다. ⑥ 데이터 막대가 차오르는 것처럼 정보를 전하는 움직임만 길게 둡니다. 누를 수 있는 모든 것(버튼·칩·탭·선택지·목록 줄)은 같은 누름 피드백을 씁니다 — 누르는 순간 `--aq-press-in`(0.04초)으로 버튼·칩·탭은 `--aq-press-btn`(.98), 줄·선택지는 `--aq-press-row`(.99)만큼 줄고, 떼면 `--aq-press-spring`(튀지도 꼬리를 끌지도 않는 곡선)으로 `--aq-press-out`(0.16초) 만에 가볍게 돌아옵니다. 짧게 톡 눌러도 눌린 모습은 최소 70ms 보입니다. `:active`만 쓰지 말고 `:is(:active,.is-pressed)`로 잡아 짧은 탭에도 보이게 하고(`lib/press.ts`, 라벨이면 `PRESSABLE`에 추가), 고를 수 없는 칸은 줄지 않습니다. 한 요소엔 움직임 하나 — 호버로 같은 요소를 밀거나 띄우지 않습니다(화살표 같은 안쪽 표시만).
20. 한 화면에는 판단 하나를 둡니다. 급한 일(보완·서명)이 있으면 홈 맨 위 큰 카드는 그 일로 바꾸고, 선택 칸은 '더 입력하기'로 접습니다. 부제는 제목을 되풀이하지 않고 새 정보(기준·기한)만 씁니다. 창을 닫는 버튼은 '취소'가 아니라 '닫기'이고, 실제로 무언가를 취소하는 버튼만 '요청 취소'처럼 무엇을 취소하는지 씁니다.
21. 간결하게 줄이더라도 돈·권리·법적 책임에 관한 문구는 줄이거나 순화하지 않습니다. 권리 확인 체크, 지급 수수료와 최소 금액, 계약 종료·해지, 거절 사유는 원래 용어 그대로, 결과가 무엇인지 함께 씁니다. 쉬운 말로 바꾸다 위험이 흐려지면(예: 고위험 거래를 가벼운 말로 부르기) 그 단순화는 하지 않습니다.
22. 글자는 놓인 면 위에서 대비 4.5:1 이상(WCAG AA)입니다. 옅은 카드(#F5F8FF·#EEF1F6)와 상태 배지 바탕까지 포함해서 잽니다. 그래서 보조 글자 회색(`--aq-gray-600`)·주황·초록·보라 글자 색과 주황 버튼 색을 한 단계 진하게 두었고, 카드 위 배지 바탕은 글자 색을 8%만 섞습니다. 새 색을 더할 때는 axe-core `color-contrast`로 확인합니다.
23. 문구는 토스 UX 라이팅 규칙을 따릅니다(앱인토스 UI/UX 가이드, 토스 8가지 라이팅 원칙). 해요체, 능동형(AUDENIQ·사용자가 한 일은 '저장했어요'·'올렸어요'·'신청했어요' — 결과·종료·확정을 알릴 때만 '확정됐어요' 같은 수동형), 캐주얼 경어('~시'·'께'·'계시다' 대신 '에게'·'있다'), 한자어 명사 풀어 쓰기('미입력' → '입력 전', '해당 파일' → '그 파일', '(보유 시)' → 선택 표시), 버튼이 하나면 '~하기', 창을 닫기만 하면 '닫기'. 문제를 알릴 때는 사용자를 탓하지 않고 할 일을 함께 씁니다. `lib/writing.test.ts`가 금지 표현을 검사합니다(법적 문서·관리자 화면 제외).
