## 함께 수정한 흐름 오류

- 만료된 PENDING 요청이 DB의 한 건 제한에 남아 새 2차 승인 요청을 막던 문제: 재요청 때 닫고 만료 감사 기록을 남긴다.
- 보완·거절 뒤 남은 요청: 닫고 취소 감사 기록을 남긴다. 대기 건수와 목록은 현재 제출본/STAGE2_REVIEW/미만료 요청만 센다.
- 승인과 보완이 동시에 일어날 때: 발매 → 승인 요청 순으로 잠금을 통일한다.
- 모든 open check가 이미 해소됐지만 재평가 작업이 없는 경우: 승인에서 재평가를 다시 예약한다.
- 다른 발매로 이동할 때: 심사 컴포넌트를 발매 ID로 초기화해 이전 데이터와 입력 상태가 남지 않게 한다.
- 진행 중 심사: 화면이 보일 때 15초 간격으로 갱신한다. 결정 입력 중에는 멈춘다. 갱신 오류는 기존 정보 옆에 표시한다.
- 2차 승인 만료 안내: 화면의 고정 72시간 문구를 실제 expires_at 기반 안내로 바꾼다. 현재 DB 기본값은 7일이다.

## 검증

테스트는 로컬에서 실행하지 않고 GitHub Actions에서 실행한다.

- Foundation: PostgreSQL 기반 전체 Rust 테스트, Clippy, WASM/Workers/Studio 브라우저/Compose 검증.
- 새 DB 회귀 시나리오: 같은 코드의 여러 트랙 경고, 실제 결과 참조와 최신 임의 PASS 분리, 읽기 전용 역할, 만료 요청 갱신, 보완 후 요청 종료, override 유효 상태, revision 감사 이력, 콘텐츠 해시가 일치하는 분석 수치.
- Admin deploy: 9개 렌더링/표시 회귀 테스트와 TypeScript 검사 및 Vite 빌드. 작업 브랜치에서는 배포 단계가 실행되지 않는다.
- 배포 순서가 엇갈려 예전 API가 응답하면 화면 조회는 유지하고 결정 버튼은 비활성화한다. 새 서버 메타데이터가 있어야 결정을 활성화한다.
- 최종 실행 ID와 결과는 PR #27의 검증 기록에서 확인한다.
