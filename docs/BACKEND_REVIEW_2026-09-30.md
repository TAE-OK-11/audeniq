## 최적화

- BER 비교는 0 위치부터 가까운 정렬을 먼저 검사해 오류 상한을 일찍 좁힌다. BER 0이면 최솟값이므로 즉시 끝낸다. 전체 유효 정렬은 유지한다.
- FFT 계획을 프로세스에서 재사용하고, 프레임별 scratch 할당을 작업별 한 번으로 줄인다. 1 CPU에서는 추가 FFT 스레드를 만들지 않는다. 기존 v2 지문 형식과 측정 결과는 유지한다.
- 보호 이름 검사에 필요한 입력 정규화·토큰화를 명단 전체에서 재사용한다. 이름의 문자 패턴을 미리 만들고, 문자 비교 중 임시 벡터 할당을 제거한다. 조직별 예외와 최신 정책은 계속 DB에서 읽는다.
- 카탈로그 유사도 검사에서 페이지별·전체 최상위 3개만 보관한다. 각 페이지의 상위 결과로 비교 상한도 좁힌다. 같은 점수는 asset UUID로 정렬하여 결과가 안정적이다. 다른 계정의 지문과 전체 페이지를 계속 검사한다.

## 검증 방법

최종 검증은 GitHub Actions의 Foundation 워크플로우에서 수행한다. 사용자 요청 이후 진행 중인 로컬 테스트는 중단했으며, 추가 로컬 테스트는 실행하지 않는다. CI는 PostgreSQL 18의 격리된 테스트 클러스터와 실제 FFmpeg/ffprobe/xmllint를 사용한다. 테스트 DB는 SQLx가 별도로 생성하며 운영 DB를 사용하지 않는다. S3/SFTP 실제 왕복 테스트도 CI의 임시 서버를 사용한다.

```sh
cargo fmt --all
git diff --exit-code
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo nextest run --locked -p audeniq-core --test-threads 4
```

CI의 성능 측정은 전체 서비스 응답 시간이 아닌 계산 함수만 대상으로 한다. 기존 기준 커밋과 수정한 소스를 같은 RustFFT 의존성과 `rustc -O`로 비교하고, 시간 측정 전에 지문 바이트와 비교 결과가 동일한지 검사한다. 967프레임 지문, 300회 비교, 3×30초 PCM의 FFT 15회를 사용한다. 결과는 Actions 로그와 `backend-review-benchmarks` 아티팩트에 기록한다.

```sh
# Foundation CI에서 전체 테스트 후 실행하는 측정 명령.
bash scripts/benchmark-fingerprint-review.sh
cargo test --locked -p audeniq-core --lib benchmark_prepared_matching -- --ignored --nocapture
```

## 적용 범위

이 변경은 백엔드 코드와 테스트를 준비한다. 운영 서비스 배포와 기존 제출 건 재심사를 자동으로 수행하지 않는다. 이미 고정된 심사 package는 기존의 불변성 정책에 따라 유지된다. 새로운 심사 및 아직 package가 고정되지 않은 재시도부터 새 참조·탐지 로직을 사용한다. DB 마이그레이션은 필요 없다.

전체 카탈로그의 정확한 지문 비교는 여전히 카탈로그 크기에 비례한다. 대규모 카탈로그의 후보 인덱스 도입은 정답 데이터로 재현율을 검증하는 별도 변경이 필요하다. 실제 서비스 p95 응답 시간, 음원 정답 데이터 기반 오탐·미탐률, 속도·피치 변경 및 역재생 탐지는 이번 검증에서 측정하지 않았다.
