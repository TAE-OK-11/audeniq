# 업로드 파일 처리와 배포 조건

음원·커버·권리 서류 업로드의 등록 조건을 `검사 → 변환 → 재검사 → 해시 고정`으로 바꿨다. 파일을 올리는 행위 자체나 알려지지 않은 모든 취약점의 부재를 보장하지 않는다. 백신만 통과했다고 원본을 신뢰하지 않으며, 검사 실패 시 제공·분석·전송을 막는 구조다.

1. 사용자는 비공개 `quarantine/`의 객체 하나에만 쓰는 10분짜리 단회 PUT 권한을 받는다. 파일 이름, 실행 프로그램, 저장 경로를 지정할 수 없다. 종류·MIME·길이를 제한하고 실제 magic bytes도 확인한다. SVG, HTML, 실행 파일, 압축 파일, Office 파일은 허용하지 않는다.
2. 완료 요청은 ETag로 고정한 별도 격리 복사본을 내려받는다. 원본 전체를 ClamAV INSTREAM으로 검사한 다음에만 파서가 실행된다. 검사기 연결 실패, 엔진 오류, 한도 초과, 미확인 응답, 120초 초과, 정의 파일 날짜 72시간 초과/미래 날짜는 등록을 허용하지 않는다. `UPLOAD_BUSY`는 완료 요청을 재시도하는 503이며 검사 생략으로 이어지지 않는다. 악성/암호화/검사 한도 탐지 결과는 `UPLOAD_UNSAFE_FILE` 422다.
3. 모든 음원은 FLAC 입력까지 무손실 FLAC으로 다시 인코딩한다. 스트림 메타데이터와 첨부 커버를 제거하고 변환 전후 PCM SHA-256을 비교한다. 원본의 AI 출처 메타데이터 신호는 격리 파서에서 읽어 별도 기록한다.
4. 커버와 이미지 서류는 정적 JPEG/PNG로 디코딩한 픽셀에서 다시 만든다. 메타데이터·추가 프레임·후행 페이로드를 전달하지 않는다. 커버는 최대 4천만 픽셀/각 변 8천 픽셀, 출력 20MiB다. ICC 변환도 샌드박스 안에서 수행한다.
5. PDF는 최대 32페이지, 페이지당 긴 변 2048픽셀, 전체 6400만 픽셀로 래스터화한다. 새로운 PDF에는 JPEG 페이지와 그리기 스트림만 넣는다. 원본의 JavaScript, OpenAction, 첨부 파일, 폼, 링크를 복사하지 않는다. 암호화 PDF는 거부한다. 검토본에는 검색 가능한 텍스트와 원본 PDF의 전자서명이 남지 않는다. 검토본을 원본 전자서명 증거로 취급하지 않는다.
6. 변환본도 다시 백신 검사하고 SHA-256·길이·ETag를 고정한다. `catalog.asset_safety`에 원본 해시/격리 키와 변환본 해시/등록 키를 함께 기록한 뒤에만 `REGISTERED`로 전환한다. 런타임 DB 역할에는 증거 수정·삭제 권한이 없고 등록/객체 재연결 트리거도 검사 증거를 요구한다. 검사·변환 중에는 DB 트랜잭션을 열어두지 않는다. 완료/취소/만료는 최종 행 잠금 아래 다시 확인한다.

전자서명 패드의 PNG도 JSON 우회 경로로 취급한다. Base64를 실제로 디코딩하고 전체 원본을 백신 검사한다. 샌드박스 안에서 CRC, 청크 순서, 정적 PNG 형식, 최대 104만 픽셀, 정확한 zlib 픽셀 스트림, 후행 바이트 부재를 검증한다. 텍스트·EXIF·ICC 등 임의 메타데이터는 거부하고 길이가 고정된 DPI/색상 속성만 허용한다. 서명/증명서의 기존 무결성 계산을 유지하기 위해 이 제한된 PNG의 검증된 원본 바이트는 그대로 기록한다. 카탈로그 draft의 중첩 이미지도 같은 검사로 등록하고, `catalog.inline_file_safety`의 해시 영수증이 없는 과거 서명/임베디드 이미지는 읽기 응답에서 숨긴다. DB 원본과 기존 증명서 해시는 보존한다. 읽기 시에는 이미지를 파싱하거나 백신을 호출하지 않고 한 번의 묶음 조회만 수행한다.

## 파서와 검사기 권한

FFmpeg/FFprobe, ExifTool, OCR, QR 검사기, 이미지/PDF 변환기 모두 Linux Landlock ABI 3 이상과 seccomp를 적용한 자식 프로세스에서 실행한다. 사용한 입력 파일과 운영체제 프로그램/라이브러리만 읽고 지정한 결과 파일 또는 고유한 0700 작업 폴더만 쓴다. DB·스토리지·KMS·파트너 환경변수를 전달하지 않는다. `/proc`, 키링, 파트너 인증 파일, 다른 업로드 파일을 허용하지 않는다. 네트워크 소켓, ptrace/process_vm, 프로세스 신호 전송, 마운트/네임스페이스 변경, io_uring 우회도 차단한다. 메모리·CPU·출력 파일·FD 한도와 기존 벽시계 제한을 함께 적용한다. 샌드박스가 지원되지 않으면 파서를 실행하지 않는다.

ClamAV 엔진은 별도 `antivirus` 컨테이너다. `network_mode: none`, 읽기 전용 루트, 비루트 UID, 모든 capability 제거, PID/메모리/CPU/tmpfs 한도를 적용한다. API와 공유하는 Unix 소켓으로 바이트만 받는다. DB·R2·KMS·파트너 비밀이나 원본 저장 볼륨을 마운트하지 않는다. 정의 파일 갱신 컨테이너 `antivirus-update`에만 외부 통신과 정의 파일 볼륨 쓰기를 허용한다. 검사 엔진은 갱신 파일을 읽기 전용으로 로드한다. 엔진을 상주시키므로 업로드마다 전체 백신 DB를 다시 로드하지 않는다. 갱신은 공식 HTTPS 주소와 로컬 CONNECT 프록시를 사용한다. 프록시는 `database.clamav.net:443` 터널만 열며 평문 HTTP 요청/다른 호스트·포트/HTTP로 바뀌는 redirect는 외부 접속 전에 거부한다. FreshClam의 인증서 검증과 TLS는 터널 끝까지 유지하며 외부 proxy 우회 환경변수를 제거한다.

## 제공·기존 파일·운영 적용

- R2 버킷은 반드시 비공개로 유지하고 `r2.dev`/사용자 도메인 공개를 끈다. `quarantine/` 또는 전체 버킷을 공개하는 CDN/Worker 경로를 만들지 않는다. 브라우저에는 원본 GET 권한을 발급하지 않는다. 이 PR은 운영 Cloudflare 설정을 적용하지 않았다.
- 관리자 문서 경로는 일치하는 검사 증거가 있는 등록 PDF/JPEG/PNG만 제공한다. 해시·길이를 재확인하며 `nosniff`, `no-store`, sandbox CSP를 적용한다. 이전의 HTML/알 수 없는 형식 다운로드 fallback은 제거했다.
- 운영 QC, 패키지 준비, 실제 전송 단계에서도 일치하는 검사 증거를 확인한다. 기존 `REGISTERED` 파일에는 새 증거를 소급해 만들지 않는다. 기존 파일은 새 업로드로 검사·변환하고 새 revision/package로 연결해야 한다. 기존 서류도 미검사 원본을 바로 제공하지 않는다. 개발 테스트의 소유자 생성 과거 fixture만 별도 취급하며 실제 완료 요청의 검사는 개발 환경에서도 필수다.
- 격리 원본은 기존 1일 lifecycle 정책의 대상이다. frozen 원본 역시 같은 prefix를 사용한다. 원본 증거를 장기 보존해야 하는 개별 업무는 보존·접근 절차를 따로 결정해야 한다. 서명된 PUT의 단회 잠금 때문에 URL 만료 전에 격리 객체를 삭제하지 않는다. 실패/취소 후 미참조 변환본은 비공개 상태로 남을 수 있으므로 객체 목록과 DB 참조를 대조하여 정리한다.
- 공식 정의 파일은 첫 `freshclam` 실행으로 내려받는다. 엔진이 준비될 때까지 업로드 완료와 PNG 서명은 503으로 닫힌다. 정의 파일 갱신 실패/72시간 초과와 컨테이너 재시작을 감시한다. 임의의 `clamd` endpoint/검사 생략 설정은 제공하지 않는다.
- 기본 백신 메모리 한도는 3GiB, 정의 갱신 한도는 1.5GiB다. `TestDatabases yes`는 갱신 시에도 엔진을 메모리에 올려 새 정의 파일을 검증하므로 갱신 컨테이너도 256MiB로 제한하지 않는다. 최대 512MiB 입력의 tmpfs 사용과 API/worker/DB를 고려하여 우선 8GiB 이상 서버를 시작 용량으로 잡고, 실제 정의 파일 로드·갱신과 최대 파일 스캔, 커버/PDF 변환을 부하 테스트하여 한도를 조정한다. 이는 이 구성의 보수적 시작값이며 실제 업무량별 측정을 대체하지 않는다. `AV_MEM_LIMIT`, `AV_UPDATE_MEM_LIMIT`, `AV_CPUS`로 조절한다. 메모리가 부족하면 등록을 열어두는 대신 서비스 확장으로 해결한다.
- `deploy.sh`는 이미지 적용 전에 실제 Docker 보안 옵션 아래 `audeniq-admin upload-sandbox-check`를 실행한다. 배포 후에도 API/worker 컨테이너에서 동일 명령을 실행할 수 있다. 커널/LSM 또는 seccomp 설정이 Landlock을 막으면 배포를 거부한다. 운영 이미지·마이그레이션·설정은 함께 배포해야 한다.

GitHub Actions는 실제 ClamAV 엔진에 무해한 EICAR 패턴을 넣어 음원/커버/PDF의 등록 및 후속 작업 차단을 확인한다. CI에는 작은 테스트 서명 DB를 사용하고 VERSION 날짜만 테스트 어댑터가 제공한다. 테스트 어댑터는 운영 이미지에 포함하지 않는다. 정상 파일 변환, 악성 PDF 기능 제거, 백신 비정상 응답/만료/부재, 런타임 컨테이너의 실제 파일·환경변수·통신 격리를 함께 검증한다. 갱신 프록시는 실제 TLS 인증서 검증과 HTTPS→HTTP redirect의 외부 접속 차단을 별도로 테스트한다. 공식 전체 정의 파일의 운영 초기화와 실서비스 부하 검증은 CI 테스트의 대체물이 아니다.
